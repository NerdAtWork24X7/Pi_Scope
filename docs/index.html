the problem

It reads, edits, runs — and then it's gone.

Your agent reads files, rewrites functions, runs test suites and hits APIs. What you are left with afterwards is a scrollback buffer: no timeline, no tool calls with exit codes, no diff, no cost, and no way back in.

001

Gone in a scroll

A finished run leaves text, not a record. The tool call that broke everything is 400 lines up, in a window you already closed.

002

Tracing means uploading

Cloud LLM tracers want your prompts, your code and your file paths inside their account. That should be a decision, never a default.

003

Watch, never act

A trace tells you what happened. It can't open a shell on that host, fix the agent's diff, or stop the run while it is still running.

004

Replay is a rewind

Scrolling back through a terminal is not a timeline. Timing, tokens and cost per turn are simply not in there.

introducing

Pi Scope is a control room, not a log file.

One server on your machine ingests the agent's event stream, writes it to a single SQLite file, and broadcasts it to the browser over Server-Sent Events. The same screen that shows you the run also gives you a real shell, an editable diff view and git checkpoints — so when the agent goes sideways, you fix it where you saw it.

built for

Developers running autonomous agents who won't ship their prompts.

◇

Private by default

One server, one SQLite file, no account. Nothing is uploaded anywhere, and the database is created mode 0600. Delete a session from the sidebar or DELETE /sessions for everything.

⊞

Yours to extend

Every header view is a plugin. Drop a folder with a plugin.json into ~/.pi-scope/plugins/ and it gets a view, its own HTTP routes, an event hook and persistent JSON state.

⌘

Agent-aware, not LLM-aware

Tool calls with exit codes, the shell's live working directory, context-window usage, compactions, model switches and branch navigation — the parts a generic tracer throws away.

install

Running in about a minute.

Node 24+ is the only real requirement — Pi Scope uses node:sqlite, which ships inside it, so there are no native build steps. Linux, macOS and Windows run the same server and dashboard.

faq

The short answers.

Do I need an account or a cloud service?+
No. Pi Scope is a single Node server on your machine that serves the dashboard and stores everything in a local SQLite file. There is no sign-up, no telemetry and no outbound network call except the ones your agent already makes.
What exactly gets captured?+
Session start and end, every user and assistant message, thinking blocks, tool calls and their results including exit codes, the LLM request arguments and system prompt, model changes, compactions and branch navigation.
Does it only work with the pi agent?+

The bundled agent is pi and Pi Scope ships its own copy of it, so Chat, the commit-message generator and the in-browser terminal work with nothing to install. But the server is agent-agnostic: anything that can POST JSON to /events can feed it, which is about ten lines of script.

Where does my data live?+
One SQLite file — db/scope.db in development, ~/.pi-scope/ when packaged — created with permissions 0600. Session data never leaves it unless you export it.
Can I use it from my phone?+
Yes, with SCOPE_HOST=0.0.0.0. A QR code in the header opens a purpose-built mobile layout — sessions, transcript, composer and stop — on any device on the same network. It does not download the desktop bundle, and it exposes a shell to that network, so only do it somewhere you trust.
Is it free?+
