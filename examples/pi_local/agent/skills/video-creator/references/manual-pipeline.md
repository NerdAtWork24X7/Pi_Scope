# Manual pipeline — schemas, commands, failure handling

Use this when you want full control of the script and shots. For a project with HTML pages, or a
one-shot brief, `vc make` runs the same steps for you. Read `references/creative-playbook.md` first.

## Pipeline at a glance

| # | Phase | Artifact | Gate (do not proceed until true) |
|---|-------|----------|----------------------------------|
| 1 | Understand | — | format + target length chosen; ≤ 1 clarifying question |
| 2 | Script | `tmp/video/script.json` | hook ≤ 3 s; one idea per beat; unique ids; non-empty `say` |
| 3 | Voice | `tmp/video/audio/voice.wav`, `tmp/video/beats.json` | beat timings measured; length within ±30 % of target |
| 4 | Plan | `tmp/video/plan.json` | every beat covered exactly once, in order; sources valid |
| 5 | Clips | `tmp/video/clips/<shot>.mov` | `vc check` prints no ERROR; clips render OK |
| 6 | Merge | `out/video.mp4` | `verify` → `"ok": true`; duration matches |

Time is the single source of truth: `beats.json` comes from the **real** voice clip; shots and frame
counts are derived from it, so the final timeline always equals the voice timeline.

## Schemas

### `script.json` (step 2 — authored)
```json
{
  "title": "Acme",
  "brief": { "goal": "…", "format": "16:9", "target_s": 45 },
  "voice": "Milo",
  "style": "warm, confident narrator, natural pace",
  "beats": [ { "id": "b1", "say": "One sentence per beat.", "intent": "hook" } ]
}
```
`id` unique, `say` non-empty. `intent` optional (free label for your own notes).

### `beats.json` (step 3 — generated by `vc voice`)
```json
{ "voice": "audio/voice.wav", "mode": "api", "total_ms": 45210, "script_sha": "…",
  "beats": [ { "id": "b1", "say": "…", "intent": "hook", "start": 250, "end": 2380 } ] }
```
`start`/`end` are milliseconds on the joined voice timeline. `script_sha` lets `check` detect a
script edited after voicing (re-run `vc voice`).

### `plan.json` (step 4 — authored)
```json
{
  "theme": { "bg": "#0C1217", "fg": "#F4F5F6", "accent": "#69D3CA", "card": "#19232C", "muted": "#64686C", "on": "#0B0F1A" },
  "format": "16:9",
  "project": "/abs/project",
  "shots": [
    { "id": "s1", "beats": ["b1"], "source": "create", "type": "hook", "text": "*three hours* a week" },
    { "id": "s2", "beats": ["b2", "b3"], "source": "browse", "url": "http://127.0.0.1:3000/?token=${SCOPE_TOKEN}",
      "actions": [
        { "at": 0, "type": "goto" },
        { "on_beat": "b2", "offset": 900, "type": "js", "expr": "() => localStorage.setItem('theme','dark')" },
        { "on_beat": "b3", "type": "click", "sel": "[data-testid=go]" },
        { "on_beat": "b3", "offset": 500, "type": "highlight", "sel": "#out" } ] }
  ]
}
```
- `shots` is a **partition of `beats.json`'s beat ids, in order** (no gaps, no repeats).
- `theme` — a **bespoke palette object** (`bg · fg · accent · card`, plus optional `muted`/`on` that
  are derived if omitted), or a curated preset *name* as a fallback. **Design it from the request**:
  `vc theme "<brief>"` designs bespoke, colour-theory, contrast-checked palettes (deterministic per
  brief; `--seed "#RRGGBB"` anchors the accent to a brand colour; `--variants N`; `--json` to pipe).
  `draft`/`make` do this automatically from the brief/`--format`/`--seed`; `--theme NAME` forces a
  preset. `check` **rejects** a malformed palette and one whose contrast is too low
  (`fg/bg ≥ 4.5`, `accent/bg ≥ 3`, `on/accent ≥ 3`). Curated fallbacks: `midnight-lime` (techy/dev) ·
  `paper-ink` (editorial/docs) · `ocean-glass` (calm/finance/health) · `sunset-pop` (playful/social) ·
  `slate-sky` (clean product/SaaS) · `ember-noir` (premium/cinematic).
- `format` defaults `16:9`.
- `source: create | asset | find | browse`.
  - `create` requires `type` ∈ `hook · stat · steps · compare · page · outro`.
  - `asset` requires `asset` (path found relative to cwd/`--work`/`project`) and optional `start` (s).
  - `find` is a placeholder: resolve with `vc fetch … --shot <id>` or switch to `create`.
  - `browse` requires `url` (path/URL) and an optional `actions` list; the page is driven and
    **captured frame-exact** (frame *i* == shot time *i*/*fps*) into the clip, so it can never drift
    against the narration. This is how demos/walkthroughs show real navigation; `page` (static image +
    camera moves) is the fallback.
- `page` shots need `src` and `focus: [{sel, label}]`.

**Browse action fields**
- Time an action with `at` (ms from the shot start) **or** `on_beat` (+ optional `offset` ms). The shot's
  first beat maps to offset 0, so the first interaction (`click`/`type`/`press`/`hover`/`highlight`/
  `scroll`) must land at ≥ 800 ms — `check` errors otherwise (`goto`/`js`/`wait` setup may run at 0).
- Types: `goto · click · type` (`sel`, `text`) `· press` (`sel`, `key`) `· hover · scroll` (`sel` or `dy`)
  `· wait` (`sel`, `state`: `visible` default, or `attached`/`hidden`/`detached`, `timeout` ms) `·
  highlight · js` (`expr`). Per-action `timeout` (ms, default 10000) bounds Playwright's auto-wait.
- **Every selector uses Playwright's engine** (`:has-text()`, `:visible`, `text=…`) in all actions, not raw
  CSS — so a selector behaves the same in `wait`, `click`, `highlight` and `scroll`.
- **Fresh context per shot:** `localStorage`, cookies, theme and auth do **not** carry over. Re-establish
  state in every shot with a `js` action, or pass it in the `url` (e.g. `?theme=dark&token=${SCOPE_TOKEN}`).
- `${VAR}` in `url`/`src` is interpolated from the environment at render time; `check` fails early if a
  referenced variable is unset. Validate actions with `vc probe` (below) before rendering.

## Command reference (see `vc <cmd> -h`)

All step commands accept `--work` (default `tmp/video`, **relative to the current working directory**) and
`--draft` (1080p at 15 fps). Keep the working folder inside the project (`tmp/video`) or under `<skill>/tmp`: a
system temp dir like `/tmp/...` is wiped between runs, so `vc` refuses it. `clips` sizes its worker pool from
the CPUs **and free memory** it can see (`--workers N` overrides it — use `--workers 2` on a small container).

| Command | What it does |
|---|---|
| `next` | prints the next action from the state of `tmp/video`, including where the last merge wrote its output |
| `draft [brief]` | web project: inspect pages (or scaffold a site) → starting `script.json` + `plan.json` |
| `voice [--tts auto\|api\|none]` | step 3: synthesizes/estimates all beats → `voice.wav` + `beats.json` |
| `check` | step 4b: validates `plan.json` vs `beats.json`, prints the shot table + chosen theme + warnings |
| `probe [--only ids] [--fast]` | step 4c: dry-runs `browse` actions with no frames — per-action `ok`/`missing`/`hidden`/`blocked` + wall time |
| `theme ["brief"] [--seed HEX] [--variants N] [--json]` | list curated palettes, or **design** bespoke, contrast-checked palettes for a request |
| `clips [--only ids] [--force] [--workers N] [--format F] [--theme T]` | step 5: renders one synced `.mov` per shot (skips unchanged; re-renders automatically when an asset or a *local* page it points at changes) |
| `merge [--out F] [--no-burn] [--music M]` | step 6: concat → MP4 + captions + chapters + player + poster + verify |
| `fetch --url U --license L [--credit C] [--name N] [--shot id]` | download a licensed asset into `assets/`, log it, attach to a shot |
| `make [brief] [--regen] [--tts …] [--out F]` | express: draft → voice → check → clips → merge |
| `doctor` | checks ffmpeg codecs, Chromium, TTS key source |
| `verify --file F [--expected S] [--strict-black] [--allow-silent]` | streams, duration, loudness, black runs, static stretches |
| `sheet --file F --out P` | 4×4 contact sheet for one-glance QA |
| `frames` / `record` | low-level capture of a single HTML scene (PNG sequence / screen recording) |
| `tts-api` / `tts-save` / `normalize` | MiMo-TTS synthesis, base64 ingest, loudness normalization |
| `assemble --manifest M` | legacy scene-manifest pipeline (prefer `clips`+`merge`) |

## Worked example

```bash
SK="<skill>/scripts/vc"
mkdir -p tmp/video
# (write tmp/video/script.json — 4 beats)
"$SK" voice --work tmp/video                      # → audio/voice.wav + beats.json
# (write tmp/video/plan.json covering b1..b4)
"$SK" check --work tmp/video                      # theme + shot table, fix ERRORs
"$SK" probe --work tmp/video                      # dry-run browse actions (~5 s) — fix missing/hidden/blocked
"$SK" clips --work tmp/video --draft              # fast preview render
"$SK" clips --work tmp/video                      # full render
"$SK" merge --work tmp/video --out out/video.mp4
"$SK" verify --file out/video.mp4 --expected 45
```

## Failure handling

- **`script.json: every beat needs a unique id and non-empty 'say'`** → fix the script, re-run `voice`.
- **`shots must cover every beat exactly once, in order`** → adjust `plan.json` `beats` arrays.
- **`script.json changed after voice`** → re-run `vc voice`.
- **`<shot>: still 'find'`** → `vc fetch --shot <id>` or set `source: create`.
- **`<shot>: url uses unset env var(s) [...]`** → export the variable, or replace `${VAR}` with a literal url; `${VAR}` is resolved at render time.
- **`<shot>: on_beat references unknown beat id(s)`** → the id must exist in `beats.json`.
- **`custom palette … must be #RRGGBB` / `custom palette <fg/bg> contrast … <` ** → the `theme` dict has a bad hex or unreadable contrast; run `vc theme "<brief>"` (optionally `--seed HEX`) and paste the JSON, or drop the dict to use a curated name.
- **`<shot>: <type> … at Nms would fire before the page is interactive (<800ms)`** → the shot's first beat maps to offset 0; add an `offset` (or `on_beat` a later beat). `goto`/`js`/`wait` may stay at 0.
- **`<shot>: <type> on '<sel>' … runs before its wait`** → reorder so the `wait` precedes the interaction, or drop it.
- **probe reports `missing` / `hidden` / `blocked`** → fix the selector, or use `state: attached` (collapsed panel), or wait for the element that reveals it. `:has-text()`/`:visible` work everywhere.
- **`<shot>: asset file not found` / `unsupported asset type`** → fix the `asset` path (images: jpg/jpeg/png/webp/bmp; video: mp4/mov/webm/mkv/m4v/avi).
- **`<shot>: type must be one of …`** → use a valid scene type.
- **`ffmpeg not found` / `playwright is unavailable`** → `vc doctor` names the broken piece and prints the
  fix: run `scripts/setup.sh` (or set `FFMPEG_BIN`); for a missing browser, `python -m playwright install
  chromium` in the skill venv.
- **A render dies with a core dump / `SIGBUS`, or imports fail after a crash** → the venv was truncated
  (interrupted install): `rm -rf <skill>/.venv && <skill>/scripts/setup.sh`, then re-run `vc clips`.
  Never hand-patch the venv; `vc doctor` verifies the binary actually *runs*.
- **An edited page does not re-render** → only file:///local targets are fingerprinted into the clip key;
  a remote url needs `vc clips --only <id> --force`.
- **`--work … is inside the system temp dir`** → the working folder must live in the project (`--work tmp/video`)
  or under `<skill>/tmp`; a system temp dir is wiped between runs and cannot hold the voice cache.
- **`…/beats.json not found`** → that step has not run yet: `vc next --work <work>` says what is missing.
- **No TTS key / API error** → retry once; on repeat use `--tts none` (silent, real timings, captions) and tell the user.
- **Animation frozen in a clip** → the scene uses non-seekable animation; only generated scene types are supported.
- **`verify` not ok** → read the `problems` list (duration mismatch, missing stream, silent audio) and fix the corresponding step.
- **`verify` warnings** → each now names the shot and time, and a richness note (`σ`/colors/edge) tells a blank page apart from rendered UI holding still; the machine-readable `findings` list carries `{shot, start, dur, kind, richness}`.
- **`audio/video length mismatch`** → the `verify` `sync` check; a clip's audio and video must each be exactly `frames/fps`. Re-run `vc clips` (capture is frame-exact, so they stay equal).
- **Captions-only (`--tts none`) build fails at the AAC step** → `loudnorm` emits NaN on digital silence; `finalize` skips normalization automatically for silent audio.

## Environment variables

| Var | Effect |
|---|---|
| `MIMO_API_KEY` / `XIAOMI_API_KEY` | TTS key (else `~/.pi/agent/auth.json` `xiaomi-token-plan-ams`) |
| `MIMO_BASE_URL` / `XIAOMI_BASE_URL` | override TTS endpoint |
| `PLAYWRIGHT_BROWSERS_PATH` | where Chromium builds live |
| `FFMPEG_BIN` / `IMAGEIO_FFMPEG_EXE` | use a specific ffmpeg binary |
| any `${VAR}` in a url/src | interpolated at render time, e.g. `SCOPE_URL`, `SCOPE_TOKEN` (see below) |

### Driving an existing local app (isolated instance)

To demo a **running** product instead of having `make` scaffold a site, point `--page` at the instance:
recipe, isolation checklist and `${VAR}` example live in SKILL.md → *Driving an existing local app*.

> **Security:** `tmp/video/plan.json` can contain a live token or internal url. Never commit or share
> `tmp/video/`; prefer `${SCOPE_TOKEN}` interpolation over literal values.
